# 服务器发布服务

> 最后更新：2026-08-01

## 运行身份

- 创建系统用户 `sitepublisher`。
- 工作目录为 `/srv/site-manager`。
- `sitepublisher` 无交互式 sudo 权限，只能通过受限规则运行 `site-managerctl` 所需操作。
- 专用公钥最终只安装到该用户的 `authorized_keys`。

## 目录结构

```text
/srv/site-manager/
├── live/                    # <slug> 原子符号链接到当前版本
├── versions/<site-id>/      # 不可变版本目录
├── staging/<upload-id>/     # .partial、元数据、解压临时目录
├── trash/<site-id>/         # 回收内容
├── registry/sites/          # 每站点独立 JSON
├── locks/                   # 每站点操作锁
└── bin/site-managerctl      # 固定管理入口
```

`slug` 创建后不可修改。显示名称和备注可修改，不影响 URL。

## 清单与只读命令

- 每个站点在 `registry/sites/<site-id>.json` 保存一份独立清单，字段与 SSH 协议中的站点清单完全一致。
- 写入先落到同目录临时文件，完成 `flush + fsync` 后通过 `os.replace` 原子替换目标文件；不会出现半写入 JSON。
- `list` 单独读取每份清单并按 `updatedAt` 倒序返回。单份文件损坏时仅向标准错误记录，不隐藏其他站点。
- `site-managerctl status --request-id <uuid>` 返回服务器 UTC 时间和磁盘总量/可用量；`list` 支持 `live`、`trash` 和 `all` 筛选。两个命令标准输出均只有一行 JSON envelope。

## 发布事务

1. `prepare` 创建唯一上传会话并检查预计空间。
2. 客户端通过 SFTP 上传到 `<upload-id>/payload.tar.gz.partial`。
3. `publish` 获取站点锁，核对大小与 SHA-256。
4. 解压到临时目录，拒绝绝对路径、`..`、设备文件和目录逃逸。
5. 要求解压根目录存在 `index.html`。
6. 将内容移动为不可变版本。
7. 原子更新 `live/<slug>`。
8. 原子写入站点清单并返回结果。
9. 清理上传会话。

任一步失败均不得改变当前 `live` 链接。

当前实现中，`prepare` 以 `requestId` 查找已有会话；同一请求与同一参数重复执行返回相同 `uploadId`。会话保存在 `staging/<upload-id>/session.json`，记录预期压缩包大小、SHA-256、创建或更新模式、站点 ID 与到期时间。空间检查要求上传包大小的两倍再加 512 MiB 安全余量。

解压器只允许普通文件和目录；拒绝绝对路径、反斜杠路径、任意 `..` 段、符号链接、硬链接、设备与其他特殊条目。解压后的根目录必须有普通 `index.html`，否则整个临时目录会被清理。

## 回收与清理

- `trash` 移除在线链接并移动站点版本，写入 `trashedAt` 和 `purgeAt`。
- `restore` 在 slug 未被占用时恢复原链接。
- systemd timer 每日运行一次 `purge-expired`。
- 默认 `purgeAt = trashedAt + 30 天`。
- 永久删除必须是幂等操作，重复请求返回当前结果而非破坏其他站点。

当前生命周期实现以站点 ID 锁串行化 `trash`、`restore` 与 `purge`。回收时先移除受控 `live/<slug>` 链接，再把完整版本目录移动到 `trash/<site-id>`，最后原子更新清单；恢复会检查原 slug 是否空闲，恢复原链接和版本目录，并清除回收时间。重复回收或恢复返回当前清单，重复永久删除返回空结果。

## Nginx

目标 URL：

```text
http://47.86.89.203/s/<slug>/
```

配置要求：

- 新增 `/s/` 静态路由并跟随受控的 `live` 符号链接。
- 默认入口为 `index.html`。
- 禁止点文件、服务器配置、私钥和源码清单。
- 不将 `.php`、`.py`、`.sh` 交给解释器执行。
- 为常见图片、视频、字体、GLB/GLTF/WASM 设置正确 MIME 类型。
- 支持 Range 请求，便于大视频和模型按需加载。
- 每次修改先备份并运行 `nginx -t`，成功后重载。

仓库提供 `deploy/nginx/site-manager-location.conf`，它只能作为 `include` 放进已确认的公开 `server { ... }` 块，且只声明 `location ^~ /s/`。该片段使用 `alias /srv/site-manager/live/`、关闭目录列表、拒绝点文件和 `.php`/`.py`/`.sh`，并为 GLB、GLTF、WASM 设置 MIME 类型。安装脚本不会猜测或改写已有虚拟主机；在实际挂载前必须先通过 `nginx -T` 找到目标 server 块、备份该文件，并在 `nginx -t` 成功后才重载。

若审计确认 80 端口空闲且现有 Nginx 不承载 HTTP，可使用隔离方案：`deploy/nginx/site-manager-nginx.conf` 具有独立 PID `/run/site-manager-nginx.pid`，仅包含 `deploy/nginx/site-manager-http-server.conf`；对应 `site-manager-web.service` 只监听 80、只允许 `/s/`，其他路径返回 404。2026-08-01 在目标服务器上采用了该方案，因此没有修改原有 Nginx 主配置、宝塔虚拟主机或 `/www/wwwroot/卫生巾数片机柜模型展示网页`。

## 安装资产与每日清理

- `deploy/install-server.sh` 默认 dry-run；只有传入 `--apply` 且以 root 运行时才会创建用户、隔离目录、Python 运行目录、`site-managerctl` 包装器、Nginx 片段、隔离 Nginx 配置和 systemd 单元。它不包含递归删除命令，也不会替换 `/var/www` 或既有网站根目录。
- Python 程序安装在 `/opt/site-manager/site_manager`，站点内容始终位于 `/srv/site-manager`。重复安装只复制包目录内容，避免生成嵌套目录。
- 包装器设置非敏感的 `SITE_MANAGER_PUBLIC_BASE_URL=http://47.86.89.203/s/`，使生产清单返回真实公开 URL；私钥、口令和令牌不进入脚本或服务器运行目录。
- `site-manager-purge.timer` 每日触发 `site-manager-purge.service`；服务以 `sitepublisher` 身份调用 `site-managerctl purge-expired`，并启用 `Persistent=true`，离线错过的清理会在下次启动后补跑。
- 安装脚本只安装 `site-manager-web.service`，不会自动启动它；只有在重新确认 80 端口空闲后才可显式 `systemctl enable --now site-manager-web.service`。这样不会抢占已有 HTTP 服务。

## 空间策略

一次更新可能同时存在旧版本、上传包、解压目录和新版本。`prepare` 至少要求：

```text
可用空间 >= 上传包估算 + 解压大小估算 + 512MB 安全余量
```

空间不足返回明确错误，不开始上传。
