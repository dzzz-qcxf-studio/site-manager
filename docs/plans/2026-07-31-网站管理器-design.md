# 网页展台管理器产品设计

> 最后更新：2026-07-31
> 状态：用户已批准

## 背景

用户经常需要向客户和同事展示只能由专业软件打开的内容。用户会先制作浏览器可访问的网页文件夹，再手工上传到阿里云服务器并分享链接。当前痛点是上传过程繁琐、旧网站位置难记、更新和删除不方便。

## 已确认需求

- 输入是已经制作好的网页文件夹，不做原始 3D、视频、图片或 PDF 转换。
- 网页根目录包含 `index.html`。
- 通常约 10MB，最大支持 2GB。
- 分享内容公开，任何拿到链接的人都能直接访问。
- 当前没有域名，链接使用公网 IP 和短路径。
- 更新站点时保持原链接不变。
- 删除后进入回收站并保留 30 天。
- Windows 软件集中展示历史站点，支持搜索、复制链接、浏览、更新、编辑、回收、恢复和永久删除。

## 方案比较与决策

### 采用：Windows 客户端直连 SSH

客户端通过专用密钥连接服务器，使用 SFTP 上传，通过受限命令发布。服务器不开放新的公网管理 API。这一方案最适合当前单管理员、单服务器的使用方式，安全边界也最小。

### 未采用：服务器管理 API

多设备和多用户扩展性更好，但当前没有域名和 HTTPS，公开管理 API 会增加认证、证书和维护成本。

### 未采用：宝塔面板自动化

初期开发量较少，但依赖面板内部接口和版本，且需要在客户端保存更高权限凭据。

## 客户端体验

主页面展示已上架网站，字段包括名称、备注、链接、大小、创建时间、更新时间、版本和状态。用户可搜索并直接复制或打开链接。

上架流程：

```text
选择文件夹 → 校验 → 填写名称/备注 → 压缩并哈希
→ 上传 → 服务端验证 → 发布 → 复制/打开链接
```

更新流程使用同一站点 ID 和 slug。回收站保留 30 天，恢复后仍使用原链接。

## 视觉方向

参考文件的视觉语言为编辑感新粗野主义：暖色纸张背景、粗描边、彩色胶囊、硬阴影和轻颗粒。桌面软件保留这一语言，但降低装饰密度，确保列表和传输状态清晰。

设计令牌和具体应用方式以 `docs/02-Windows客户端.md` 为准，视觉快照见 `docs/assets/site-manager-style-reference.png`。

## 服务器设计

内容放在 `/srv/site-manager`，按 live、versions、staging、trash 和 registry 分离。每个版本先完整验证，再原子切换线上符号链接；失败时旧版本继续服务。

Nginx 只新增 `/s/` 静态路由，现有根网站不变。生产管理使用 `sitepublisher` 受限用户，不使用 root。

## 可靠性与安全

- 流式处理 2GB 内容，避免整体载入内存。
- SFTP `.partial` 续传，操作使用 requestId 幂等。
- SHA-256 同时在本机和服务器验证。
- 拒绝目录逃逸、外部链接、私钥和环境文件。
- 独立站点清单避免单文件损坏导致全部数据丢失。
- Nginx 配置修改前备份、验证失败回滚。
- 固定 SSH 主机指纹，私钥不进入项目。

## 非目标

第一版不包含：

- 原始文件自动转换或在线编辑器。
- 分享密码、访问到期时间或账号系统。
- 访问统计和客户行为分析。
- 多管理员权限和公网管理 API。
- 域名、自动 HTTPS 和 CDN。

## 成功标准

1. 从选择文件夹到取得链接可在一个流程内完成。
2. 10MB 普通站点快速发布，最大 2GB 不发生内存溢出。
3. 更新成功后 URL 不变，失败时旧版本不受影响。
4. 历史站点可搜索，不需要记服务器路径。
5. 删除后 30 天内可恢复原链接。
6. 断网重连能够续传。
7. 不破坏服务器现有网站和其他服务。
