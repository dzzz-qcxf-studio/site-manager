# Windows 客户端

> 最后更新：2026-08-02

## 产品定位

客户端暂定名“网页展台”，面向单个管理员使用，第一版为简体中文 Windows 桌面程序。

## 当前实现状态

- `SiteManager.App` 已建立 .NET 8 WPF 应用壳，默认窗口为 1180×760，最小尺寸为 1024×640。
- 默认进入“已上架网站”，左侧导航可切换已上架、上架网站、传输中心、回收站和设置；导航状态由 `ShellViewModel` 管理并有自动化测试。
- 首屏当前显示“尚未连接服务器”和空站点状态，数量与空间使用 `—`，不得将预览数据误认为服务器事实。
- 视觉令牌拆分在 `Resources/Colors.xaml`、`Typography.xaml` 和 `Controls.xaml`，界面不直接调用 SSH 或基础设施实现；字体资源同时保留 `UiFont` 与 `DisplayFont` 别名，兼容已有页面。
- 已上架、上架、传输中心、回收站和设置页均已接入对应 ViewModel。`App.xaml.cs` 在启动时异步装配 SSH.NET、SFTP、SQLite 与设置存储，不在 WPF UI 线程上同步阻塞；没有已保存的配置时仍使用明确空态和错误提示，不会填充伪造站点数据。
- 主窗口左下角的服务器状态卡片绑定实际启动配置：读取到设置文件时显示已配置的服务器地址，没有配置时才显示未配置提示。
- 已上架网站和回收站共享 `SiteCatalogState`：同步、回收、恢复和永久删除完成后会用同一份站点快照刷新两个页面；远程操作通过异步互斥门串行执行，避免跨页面竞态和过期选中项误操作。
- 页面顶部只保留当前页面标题和说明，不再显示蓝色“管理工作台”标签。
- 当前运行预览归档于 `docs/assets/site-manager-wpf-preview-v1.png`。Core 已提供 `PublishSiteService` 和 `SiteSyncService`：发布会按校验、归档、远端准备、保存检查点、续传上传、验证、发布、缓存更新和删除检查点的顺序执行。
- `scripts/publish-win-x64.ps1` 会先运行 Release 测试，再生成自包含单文件 Windows x64 程序、README、非敏感设置模板、ZIP 与 SHA-256 文件；产物目录 `artifacts/` 被 Git 忽略，不会提交私钥或本机设置。

## 主要页面

### 已上架

- 显示名称、备注、分享链接、空间、创建时间、更新时间、版本和状态。
- 支持按名称、备注和链接搜索。
- 操作：复制链接、浏览器打开、更新、编辑、移入回收站。
- 修改名称或备注不改变 `slug` 和分享链接。
- 当前实现支持同步、搜索、复制链接、在浏览器打开、移入回收站和更新；选择“更新”会将既有站点 ID 带到上架页，后续发布保留原 `slug`。
- 复制链接遇到 Windows 剪贴板暂时被占用时会自动短暂重试；最终失败会显示错误提示，不会让异步命令导致程序退出。
- 已配置服务器时，启动会先读取 `%APPDATA%/SiteManager/cache.db` 中上次成功同步的站点并立即显示；窗口显示后自动执行一次后台同步，成功后用服务器清单替换并持久化缓存。

### 上架网站

1. 选择网页文件夹。
2. 扫描并要求根目录存在 `index.html`。
3. 填写显示名称和可选备注。
4. 展示文件数量、原始大小、压缩估算和风险提示。
5. 执行压缩、上传、校验和发布。
6. 成功后提供复制链接和浏览器打开。

当前实现支持手动输入网站目录、扫描校验、填写名称/备注、开始发布与取消，并可接收已有站点的更新请求。发布命令在目录通过校验且名称非空前保持禁用；归档路径在 `%LOCALAPPDATA%/SiteManager/archives` 下按请求 ID 创建，不保存私钥内容。发布失败时错误横幅使用独立的 `HasError` 布尔状态显示，便于定位 SSH、SFTP 或服务端协议错误。
- 上架页和更新页不再放置“新建网站”按钮；通过主窗口右上角唯一入口“上架新网页”进入时会清除已有站点 ID，下一次发布会创建新的独立网站，不会覆盖原项目。
- 点击“开始上架”后会立即切换到“传输中心”，用户可以在耗时的压缩和上传过程中持续看到任务状态。
- 更新已有站点时，会从 `%APPDATA%/SiteManager/site-folder-paths.json` 恢复该站点上次使用的本地网页文件夹；更新任务开始前就会保存用户当前选择的目录，发布成功后也会写入最终站点 ID。升级前已经创建、且本地从未保存过目录记录的旧站点无法从服务器反推出 Windows 路径，需要手动选择一次，之后即可自动恢复。

### 传输中心

- 显示扫描、压缩、上传、服务端验证和发布阶段。
- 显示字节进度、速度、剩余时间和明确错误。
- 进度条对只读进度属性使用单向绑定，避免 WPF 在布局阶段尝试回写进度值。
- 支持取消；网络中断后允许从服务端 `.partial` 大小续传。
- 软件重启后从本地任务记录恢复。
- 当前任务结束后会写入“传输历史”，记录名称、源文件夹、完成时间、最终阶段和成功/失败/取消状态；历史最多保留最近 100 条，保存在 `%APPDATA%/SiteManager/transfer-history.json`。

当前实现展示共享的当前传输名称、固定发布阶段和已确认字节进度，并在任务结束后追加持久化历史；真实 SSH/SFTP 适配会根据服务端 `.partial` 长度执行续传，失败后的检查点保留在本地 SQLite 中。

### 回收站

- 显示删除时间、预计清理时间和占用空间。
- 支持恢复和立即永久删除。
- 默认保留 30 天。
- 回收站卡片通过 `ListBoxItem.HorizontalContentAlignment=Stretch` 撑满内容卡片宽度，项目多行时保持统一的父容器布局。

当前实现支持同步、恢复及永久删除确认。永久删除必须先经 `IConfirmationService` 明确确认，取消确认时不调用远端清理。

### 设置

- 服务器 IP、SSH 端口、用户名、私钥路径、主机指纹、公开基础 URL。
- “测试连接”只执行只读状态命令。
- 敏感字段不得写入源码；私钥只保存路径。

设置保存到 `%APPDATA%/SiteManager/settings.json`，以临时文件替换方式写入；文件只包含经过校验的连接资料和私钥路径，不包含私钥正文或口令。保存后提示重启应用，以便重新组合发布、同步和缓存服务。测试连接会通过严格主机指纹校验调用一次 `site-managerctl status`，不会上传、发布或修改服务器状态。

## 应用分层

```text
SiteManager.App             WPF Views、Resources、ViewModels
SiteManager.Core            领域模型、校验、状态机、用例接口
SiteManager.Infrastructure  SSH、SFTP、压缩、SQLite、配置
```

UI 不直接调用 SSH.NET；所有远程操作通过 `IRemotePublisher`，便于测试和替换。

## 本地状态

本地数据库只缓存：

- 最近同步的网站清单。
- 未完成传输任务及远端 `.partial` 标识。
- 非敏感界面设置。

此外，站点上次使用的本地源文件夹和最近传输历史分别保存在 `%APPDATA%/SiteManager/site-folder-paths.json` 与 `%APPDATA%/SiteManager/transfer-history.json`，两者均不包含私钥或口令。

服务器的独立站点清单是最终事实来源，删除本地缓存后能够重新同步。

## 文件校验

- 根目录必须存在精确小写的普通文件 `index.html`；`Index.html` 等其他大小写不视为入口文件，缺失时返回 `INDEX_MISSING`。
- 内容总量最大为 2 GiB（`2 * 1024 * 1024 * 1024` 字节），仅大于该值时返回 `TOO_LARGE`；扫描结果同时返回普通文件总数和总字节数。
- 根目录及其中任意符号链接、目录联接或其他重解析点均返回 `REPARSE_POINT`。扫描器先读取当前条目的属性，确认它是普通目录后才进入，因此不会跟随链接逃出根目录或陷入循环；重解析点目标不计入文件数和字节数。
- 下列内容按 Windows 不区分大小写匹配并返回 `SENSITIVE_FILE`：名为 `.git`、`.ssh` 的任意目录段，`.env`、`.env.*`、`id_rsa`、`id_ed25519`，以及扩展名为 `.pem`、`.key` 的文件。敏感目录只在目录自身记录一次问题，扫描器不会进入或统计其内部内容，内部文件不可访问或发生瞬时变化也不会中断其余扫描。
- `node_modules` 不阻止发布，返回非错误的 `NODE_MODULES` 警告，并继续统计其中普通文件；客户端不得静默删除内容。
- 相对路径在校验结果中统一使用 `/` 分隔，便于界面稳定展示。
- 压缩和哈希必须流式执行，不能把 2GB 内容整体载入内存。

## 发布归档

- 客户端使用 `TarGzipArchiveBuilder` 将已校验的网站目录流式写入 `tar.gz`，归档仅包含按名称排序的普通文件相对路径，分隔符统一为 `/`。
- 打包阶段会再次拒绝根目录或子项中的重解析点，降低“校验完成后目录被替换”的竞态风险；输出包不得位于源目录内部。
- `ArchiveResult` 返回源文件总字节数、压缩包字节数和压缩包本身的 64 位小写 SHA-256，上传与服务端验证复用该值。
- 输出使用新建语义，不覆盖已有文件；取消或中途异常只删除本次新建的不完整归档，预先存在的目标文件保持不变。

## 发布、更新与同步用例

- `PublishSiteRequest` 必须携带非空 `requestId`、源网站目录、归档输出路径、名称、备注和可选的既有 `siteId`。同一个请求 ID 可在重启后重新 `prepare`，用于安全续传。
- `PublishSiteService` 通过抽象接口协调 `IWebsiteFolderValidator`、`IArchiveBuilder`、`IRemotePublisher`、`ResumableUploadEngine` 和 `ISiteCache`；界面不直接调用 SSH.NET 或 SQLite。
- 本地检查点在远端上传会话创建后、开始写入任何远端字节前保存；只有远端原子发布和本地缓存更新均完成后才删除。发布失败或取消时保留检查点。
- 更新会将原 `siteId` 传至服务器，服务器负责保留不可变 `slug`，因此客户已收到的公开 URL 不会变化。
- `SiteSyncService` 获取服务器的完整清单并在单个缓存替换操作中更新本地副本；离线缓存不视为服务器事实。
- 进度以 `PublishProgress` 暴露固定阶段：`Scanning`、`Archiving`、`Preparing`、`Uploading`、`Verifying`、`Publishing`、`Completed`、`Failed`、`Cancelled`。

## 可续传上传

- `ResumableUploadEngine` 先读取远端 `.partial` 长度，再将本地归档流和远端流同时定位到该字节偏移；远端长度超过本地归档时立即失败，防止错误拼接。
- 上传以 1 MiB 分块进行，进度以“远端已确认字节 / 本地总字节”报告，且只会单调递增。
- 取消会停止继续写入，但不截断远端 `.partial`；下次 `prepare` 返回同一会话时可以从保留长度续传。

## 本地缓存与任务恢复

- `%APPDATA%/SiteManager` 下的 SQLite 缓存只保存最近同步的站点清单和未完成传输检查点；缓存清空后可从服务器重新同步。
- 站点缓存替换在单个 SQLite 事务内完成。检查点保存请求 ID、上传 ID、可选站点 ID、归档路径、远端临时路径、哈希、总字节和已知远端偏移，供重启后恢复。
- 数据库不保存私钥正文、口令或任何服务器文件内容；删除检查点可重复执行。
