## 本机配置

默认配置文件位于用户应用数据目录，不进入仓库：

```text
%APPDATA%/SiteManager/settings.json
```

配置结构：

```json
{
  "schemaVersion": 1,
  "host": "47.86.89.203",
  "sshPort": 22,
  "username": "sitepublisher",
  "privateKeyPath": "%USERPROFILE%/.ssh/site_manager_ed25519",
  "hostKeySha256": "SHA256:ZrZ2SF13RvyeSsLMuHl27GIelk8Yb09f1PBBae/1tbU",
  "publicBaseUrl": "http://47.86.89.203/s/",
  "trashRetentionDays": 30
}
```

不得保存私钥正文、口令、API Key 或 root 密码。

客户端保存或使用配置前必须验证：SSH 端口为 1–65535，用户名符合 Linux 安全用户名格式，私钥路径非空，主机指纹为无填充的 OpenSSH `SHA256:` 指纹，公开基础 URL 为无查询参数的 `http(s)://<host>/s/`。指纹不匹配时连接必须中止，不允许“忽略并继续”。

当前客户端通过设置页读写该文件。保存采用临时文件替换，避免写入中断留下半份 JSON；仅保存连接资料和私钥路径。应用启动时读取配置并组合实际的 SSH/SFTP 发布服务，设置变更后需重启应用才会让已创建的页面服务使用新配置。“测试连接”仅调用 `site-managerctl status`，可用于在发布前验证私钥、网络、主机指纹和受限账号权限，且不会修改服务器内容。

## 首次服务器安装

安装脚本必须可重复执行并完成：

1. 检查 Ubuntu 版本、磁盘、端口和现有 Nginx。
2. 创建 `sitepublisher` 用户和 `/srv/site-manager` 目录。
3. 安装专用公钥并设置严格权限。
4. 安装 `site-managerctl` 和 systemd 清理 timer。
5. 安装 `/s/` Nginx 片段及可选的隔离 Nginx 配置。
6. 对将使用的 Nginx 配置执行 `nginx -t`，成功才启动或重载。
7. 运行只读 `status` 和测试站点发布。
8. 验证后从 root 的 `authorized_keys` 删除“网站管理器专用”公钥，保留用户原有公钥。

第 8 步属于安全敏感变更，执行前必须再次确认目标公钥指纹和剩余 root 登录方式。

### 安装脚本的安全使用方式

安装资产位于 `deploy/`。先在服务器上取得完整仓库副本或仅临时上传该目录和 `server/`，再执行：

```bash
sudo ./deploy/install-server.sh --dry-run
```

默认模式只显示将要执行的命令，不创建用户、目录或配置。确认输出后才可执行：

```bash
sudo ./deploy/install-server.sh --apply --source-dir /root/site-manager-source --authorized-key-file /root/sitepublisher.pub
```

脚本只安装 `/srv/site-manager`、`/opt/site-manager`、`/usr/local/bin/site-managerctl`、Nginx snippet、隔离 Nginx 配置和 systemd 单元；不删除现有网站根目录，也不会自动把 snippet 插入未知的 Nginx 虚拟主机。通过只读 `nginx -T` 确认承载 `47.86.89.203` 的 `server` 块后，备份该配置并在其内部加入：

```nginx
include /etc/nginx/snippets/site-manager-location.conf;
```

然后执行 `nginx -t && systemctl reload nginx`。这一步会修改现有 Nginx 配置，必须在服务器 Gate 检查及备份后进行。

如果审计确认 80 端口空闲而现有 Nginx 不承载 HTTP，可不改写现有 Nginx：先执行 `nginx -t -c /etc/nginx/site-manager-nginx.conf`，再显式执行 `systemctl enable --now site-manager-web.service`。该独立服务使用自己的 PID 文件，只响应 `/s/`，根路径及其他路径一律返回 404。目标服务器已采用此方案。

### 一键安装（推荐新服务器使用）

如果服务器是全新 Ubuntu/Debian，且 80 端口没有被其他 HTTP 服务占用，可以使用编排脚本自动完成依赖安装、源码下载、`sitepublisher` 创建、Nginx/systemd 安装和服务启动。脚本只安装公钥，不会读取或上传 Windows 私钥。

先从 Windows 把专用公钥上传到服务器：

```powershell
scp "$env:USERPROFILE\.ssh\site_manager_ed25519.pub" root@47.86.89.203:/root/sitepublisher.pub
```

然后登录服务器执行：

```bash
curl -fsSL https://raw.githubusercontent.com/dzzz-qcxf-studio/site-manager/main/deploy/one-click-install.sh \
  -o /tmp/site-manager-one-click-install.sh
chmod 700 /tmp/site-manager-one-click-install.sh
sudo /tmp/site-manager-one-click-install.sh \
  --public-key-file /root/sitepublisher.pub \
  --server-host 47.86.89.203
```

脚本会在 80 端口已被占用时安全停止，不会修改未知的现有 Nginx `server {}`。这种情况请改用上面的 Nginx snippet 方式。执行结束后，终端会打印公开基础 URL 和 SSH 主机指纹，复制到 Windows 客户端“设置”页即可。

- Nginx 配置始终先 `nginx -t`。
- 升级失败时恢复脚本、配置和 systemd 单元，不动网站内容。
