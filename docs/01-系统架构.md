# 系统架构

> 最后更新：2026-08-01
> 实施状态：Task 1–17 已完成（Task 12 已提前完成）；领域规则、发布服务、续传上传、本地缓存、发布/更新/同步编排、WPF 业务页、设置持久化、真实 SSH/SFTP 适配、生产服务器部署、端到端验收和 Windows x64 自包含软件包均已完成。

## 目标

在一台 Windows 电脑上集中管理 `47.86.89.203` 的静态展示网站，解决手工上传繁琐、旧链接难查、更新易中断和误删难恢复的问题。

## 架构选择

采用“Windows 客户端直连 SSH”的架构，不对公网暴露管理 API。

```text
Windows WPF 客户端
├─ 本地文件扫描、校验与压缩
├─ SSH/SFTP 上传和远程命令
├─ 本地缓存与任务恢复
└─ 中文管理界面
          │ SSH 22
          ▼
Ubuntu 22.04
├─ sitepublisher 受限用户
├─ site-managerctl 固定管理命令
├─ /srv/site-manager 内容与清单
└─ site-manager-web 独立 Nginx：/s/<slug>/ 静态访问
          │ HTTP 80
          ▼
客户、同事的普通浏览器
```

## 技术栈

- 客户端：.NET 8、WPF、MVVM。
- SSH/SFTP：SSH.NET `2025.1.0`。
- MVVM：CommunityToolkit.Mvvm `8.4.2`。
- 序列化：`System.Text.Json`。
- 本地缓存：SQLite，仅作缓存和任务恢复，服务器清单是事实来源。
- 测试：xUnit v3 `3.2.2`。
- 服务器：Ubuntu 22.04、Bash/Python 标准库管理脚本、Nginx、systemd timer。

选择 .NET 8 是因为当前开发机已安装 .NET 8 SDK 与 Windows Desktop Runtime，可避免在设计阶段引入额外 SDK 安装。

## 站点领域模型

客户端 Core 层以 `SiteManifest` 表示服务器返回的单站点清单，字段包括唯一 ID、名称、备注、不可变 slug、状态、版本、内容大小、SHA-256、创建/更新时间及可选的回收/清理时间。`SiteStatus` 当前只定义 `Live` 与 `Trash`，公开链接统一由基础 `/s/` 地址和不可变 slug 组成，并始终保留尾部斜杠。

该模型是客户端与后续发布协议共享的最小领域基线；站点清单仍以服务器数据为事实来源，本地只缓存其副本。

## 核心边界

### 客户端负责

- 选择和扫描网页文件夹。
- 校验 `index.html`、路径和敏感文件。
- 流式压缩、SHA-256、续传和进度展示。
- 调用固定远程命令，不拼接任意 shell。
- 缓存网站清单和未完成任务。

### 服务器负责

- 再次验证上传包、大小、校验值和入口文件。
- 创建不可变版本并原子切换在线链接。
- 保存每站点独立清单。
- 回收、恢复、保留 30 天和自动清理。
- 以静态方式向浏览器提供 `/s/` 内容。

### 浏览器访问者

- 不需要登录，拿到链接即可访问。
- 只能读取静态文件，不能执行管理操作。

## 数据流

### 首次发布

```text
选择文件夹 → 本地校验 → 流式压缩 → 计算 SHA-256
→ SFTP 上传 .partial → 服务端校验 → 解压到新版本
→ 原子创建 live 短链接 → 写入站点清单 → 返回 URL
```

### 更新

```text
上传新版本 → 完整验证 → 原子切换 live 短链接
→ 旧版本暂留用于回滚 → 原 URL 继续有效
```

## 发布用例编排

`PublishSiteService` 只负责协调 `IWebsiteFolderValidator`、`IArchiveBuilder`、`IRemotePublisher`、`ResumableUploadEngine` 和 `ISiteCache`，不包含 WPF、SSH.NET 或 SQLite 细节。固定执行顺序为：扫描与校验、归档、远端准备、保存检查点、续传上传、服务器验证、原子发布、更新本地缓存、删除检查点。

每次发布都带有稳定的非空 `requestId`；更新操作同时传递已有 `siteId`，由服务器保留既有 `slug`，因此公开 URL 不变。校验失败时不会开始归档或远端调用；远端发布未成功时不会删除本地检查点，可在重启后重新准备同一请求并续传。发布完成后的缓存只是加速界面展示，服务器清单仍是事实来源；`SiteSyncService` 会以服务器返回的完整清单原子替换本地缓存。

发布进度阶段固定为 `Scanning`、`Archiving`、`Preparing`、`Uploading`、`Verifying`、`Publishing`、`Completed`、`Failed`、`Cancelled`，供后续 WPF 传输中心统一显示。

### 删除与恢复

```text
在线站点 → 移除 live 链接 → 移入 trash → 记录 purgeAt
恢复 → 移回 versions → 重建相同 slug 的 live 链接
过期 → systemd timer 永久清理
```

## 安全边界

- 管理通道仅开放现有 SSH 22 端口。
- 客户端固定服务器 SSH 主机指纹。
- 生产管理使用 `sitepublisher`，不使用 root。
- `site-managerctl` 只接受白名单子命令和严格参数。
- SSH.NET 适配只构造协议中列出的固定 `site-managerctl` 命令；文本参数使用 Base64URL，主机指纹不匹配或未收到指纹时中止连接。
- 网站目录拒绝路径穿越、外部链接、私钥、`.env` 和版本库元数据。
- Nginx `/s/` 仅提供静态文件，禁止脚本执行和点文件访问。
- 私钥位于 Windows 用户 `.ssh` 目录，不进入项目或安装包。
- 当前无域名，因此公开内容使用 HTTP；管理操作始终走加密 SSH。

## 兼容现有服务

服务器已有 Nginx、宝塔、Python、MySQL 和其他服务。2026-08-01 的实机审计确认已有 Nginx 实例只承载 26079 TCP 转发、80 端口空闲，因此本项目使用独立 PID 与独立配置的 `site-manager-web.service` 监听 80；它不替换已有 Nginx 主配置或 `/www/wwwroot` 内容。安装过程必须：

1. 在变更前备份目标 Nginx 配置。
2. 使用独立 `/srv/site-manager` 目录。
3. 只新增 `/s/` 路由，不替换现有网站根目录。
4. 运行 `nginx -t` 后才重载。
5. 失败时恢复备份。

现有“卫生巾数片机柜模型展示网页”必须保持可访问且不纳入自动清理。
